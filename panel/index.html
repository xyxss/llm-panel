Model directory

re-reads every folder and writes what it finds back into the config
Detects, per folder: which GGUF is the main build, whether it embeds a NextN/MTP head, whether a projector sits beside it (so vision can be turned on), any mtp-*.gguf draft heads, and the real on-disk size. Run it after you move a model, drop in an mmproj-*.gguf, or finish a download. New folders are registered automatically — one entry per build, so a plain and a -mtp GGUF in the same folder stay separate models.

extra llama-bench flags

            

              llama-bench cannot measure MTP. It has no --spec-type or
              -md, so speculative decoding has to be compared by actually running
              the server — apply the preset and read tok/s from the dashboard. Everything else
              (experts on CPU, load mode, KV type, batch, threads) is settled here, faster and
              without restarting anything.
            

            

              
              
              
              
            

          

        


        

          
Server benchmark — the MTP one

            actually runs each preset and measures real completions

          

            

              Starts the preset, waits for it to load, sends real requests, reads llama.cpp's
              own timings, then moves to the next variant and stops the server at the end.
              Slower than the sweep above — minutes per variant — but it is the only way to
              measure speculative decoding, because llama-bench has no
              --spec-type. With no variants given it compares the preset at
              MTP off / n=2 / n=3, which is the question worth asking.
              This restarts the model server.
